# What a model can read

Every model crucible offers reads text. Some of them also read pictures, PDFs or
video, and which ones do is not something crucible works out from a name — it is
read from the same published table of model limits that holds each model's
[window](providers.md), regenerated by a script and checked in, so the answer
here is whatever that table said when this build was made.

| Provider | Model | Reads |
| --- | --- | --- |
| `anthropic` | `claude-fable-5`, `claude-opus-5`, `claude-sonnet-5`, `claude-haiku-4-5` | text, pictures, PDFs |
| `moonshot` | `k3`, `k3-256k`, `kimi-for-coding`, `kimi-for-coding-highspeed` | text, pictures, video |
| `openai` | `gpt-5.6-sol`, `gpt-5.6-terra`, `gpt-5.6-luna`, `gpt-5.5` | text, pictures, PDFs |

A model crucible has never heard of is not in that table and has no row here.
crucible knows nothing about what it reads, which is a different answer from
knowing that it reads nothing — the same distinction the window lookup makes,
and for the same reason: a fact borrowed from a model one word away is wrong in
a way nobody notices until a session has already gone wrong.

## What crucible puts in a request

The table above is about the models. What a request actually carries is decided
by the protocol crucible speaks to that provider, and each of the three has its
own way of spelling a picture — Anthropic Messages an `image` block, OpenAI
Responses an `input_image` part, Moonshot a `data:` URL inside an `image_url`.

crucible writes text. A model reading more than text is a fact about the model,
and this page records it because it is worth knowing when you choose one.
